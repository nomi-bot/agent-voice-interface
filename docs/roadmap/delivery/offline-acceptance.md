## Development and verification order

1. **P0 · integration review.** Review the Live gateway sync, existing browser and simulator candidates, the socket stability runner, then the cross-milestone candidate against `dev`. #21 is a historical review branch. Run the negative authorization, disconnect-during-submit, duplicate-call, restart and rollback cases before deployment.
2. **P0 · provider qualification without devices.** Use a dedicated zero-tools Hermes profile and an operator-selected Gemini Live model. Run the pinned Hermes restart probe, then the synthetic prerecorded voice flow. Verify one task execution, the returned content, denial before dispatch, failure handling and ordered recovery. Record transport, model and inputs by fixture identifier.
3. **P1 · reproducibility and resilience.** Repeat the browser, Python SDK, Jazzy graph, wheel-install and 30-minute paced TCP gates on the release candidate. Track a clean socket close, grant expiry, repeated/late cancellation, a long-running task, idempotent retry and result retention. Record CPU, memory, sample counts, errors and usage for each scenario.
4. **Deferred · physical audio.** Run the two-turn headset/speaker procedure, barge-in/echo and device-loss scenarios after review. Measure end-of-user-turn → first audible output and user-speech detection → audible stop on one client clock. The provisional targets are median 1.2 s and p95 300 ms respectively. Physical robot or actuator control is outside the approved v0.1 scope.

## Scope of the measurements

A mock PCM mirror checks delivery of known bytes. Chromium fake devices additionally exercise microphone acquisition, AudioWorklet playback and the rendered interface. A local ROS graph exercises a publisher and subscriber using the synthetic action. A pinned Hermes daemon with deterministic model exercises the actual HTTP adapter and task lifecycle. A Gemini run with fixture audio requires provider credentials. Only an acoustic observation can establish the audible latency targets.

The pinned Hermes API exposes status, result and stop acknowledgement. The observable event history can be replayed by cursor. Provider-native token progress and blind retries after a lost submission receipt are unsupported by the pinned interface. Unknown execution remains pending reconciliation. Voice provider GoAway closes the voice connection; recovery opens a new authenticated session. Open protocol proposals such as general transcript messages, codec negotiation and seamless provider-context resumption still require a product/contract decision.
